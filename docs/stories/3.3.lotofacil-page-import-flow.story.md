# Story 3.3: Fluxo local de importação da página Lotofácil CAIXA

**Status:** Done
**Epic:** 3 — CAIXA e laboratório
**Prioridade:** P0
**Fonte:** [PRD — FR-03, NFR-03, NFR-07](../prd.md)

## História

Como operador local, quero registrar um snapshot HTML da página oficial da
Lotofácil usando o parser validado, para manter cada tentativa auditável e criar
um `DatasetSnapshot` somente quando o resultado for válido.

## Decisão de reutilização

| Capacidade | Decisão | Justificativa |
| --- | --- | --- |
| Parser da página | Usar contrato existente | A Story 3.2 é a fonte de verdade para interpretar e validar o conteúdo. |
| Proveniência/snapshot | Usar contrato existente | A Story 3.1 define as importações, transação e imutabilidade. |
| Orquestração CLI local | Criar | Conecta parser e persistência sem criar cliente de rede. |
| Sincronização assíncrona | Restringir | Será incremento posterior de FR-03. |

## Critérios de aceite

1. `data import-lotofacil-page --input PATH` lê apenas o HTML local, executa o
   parser canônico e registra a proveniência usando a fonte oficial e a versão
   do parser. (PRD: FR-03, NFR-03)
2. Conteúdo válido cria importação `VALIDATED` e snapshot imutável em transação;
   a saída inclui resultado normalizado, identidade do import e snapshot. (PRD:
   FR-03, NFR-03)
3. Conteúdo inválido ou com placeholder cria importação auditável `INVALID`, sem
   snapshot, e preserva o último snapshot válido. (PRD: FR-03, NFR-03, NFR-07)
4. Testes cobrem os dois caminhos, fallback e CLI offline. (PRD: NFR-07)
5. Não há fetch, API, browser automation, catálogo, histórico, estratégia,
   geração, cobertura, impressão ou UI. (PRD: §1.2, FR-03–FR-05)

## Dev Agent Record

### Completion Notes

- Adicionado `data import-lotofacil-page`, que compõe parser da Story 3.2 e a
  persistência imutável da Story 3.1.
- Página válida cria importação `VALIDATED`, resultado normalizado e snapshot;
  rejeição do parser cria importação `INVALID` sem snapshot.
- O último snapshot válido permanece disponível após uma importação inválida.
- Falha de leitura do caminho de entrada é tratada antes do parser, retorna
  código 1 e não tenta registrar conteúdo inexistente como página inválida.
- Falha SQLite após parsing válido não é mais reclassificada como rejeição do
  parser e não cria envelope `INVALID` depois do rollback.
