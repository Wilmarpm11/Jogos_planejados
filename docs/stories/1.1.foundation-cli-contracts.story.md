# Story 1.1: Fundação CLI e contratos de domínio

**Status:** Done  
**Epic:** 1 — Fundação técnica  
**Prioridade:** P0  
**Fonte:** [PRD](../prd.md), [Arquitetura](../architecture.md)

## História

Como operador do produto, quero uma fundação executável por CLI com contratos de
domínio versionados, para que futuras funcionalidades sejam construídas sem
alterar a fórmula, o histórico ou a impressão por acidente.

## Escopo

Criar o monorepo npm, o comando CLI inicial, contratos de domínio em TypeScript,
uma camada SQLite local inicial e a configuração de qualidade. A story não
implementa Lotofácil, E1-E10, geração, cobertura, sincronização CAIXA, PDF,
desktop ou INJOLOCA.

## Decisão de reutilização

| Capacidade | Decisão | Justificativa |
| --- | --- | --- |
| Contrato de modalidade | Criar contrato reutilizável | Será compartilhado por todas as loterias. |
| Identidade/hash de saída | Criar contrato reutilizável | Protege auditoria e impressão futuras. |
| Persistência SQLite | Criar contrato reutilizável | Mantém snapshots e carteiras locais consistentes. |
| Métricas Lotofácil | Fora desta story | Regra específica, será módulo da Lotofácil. |
| Impressão | Fora desta story | Exige contrato e ensaio próprios em story posterior. |

## Critérios de aceite

1. Existe um monorepo npm com workspaces para `apps/cli` e os pacotes
   `domain-core`, `lottery-contracts` e `data-access`.
2. `npm run lint`, `npm run typecheck` e `npm test` existem na raiz e
   passam em instalação limpa.
3. O comando `npm run cli -- --help` funciona e apresenta comandos de
   diagnóstico, sem exigir interface desktop.
4. `LotteryDefinition`, `ApprovedStrategyConfig`, `GenerationRequest`,
   `FrozenPortfolio` e versões de contrato existem como tipos públicos e têm
   validação de runtime.
5. O contrato de geração não possui campo nem dependência para histórico bruto;
   um teste prova essa fronteira.
6. A identidade canônica de uma carteira e o `portfolio_hash` têm algoritmo,
   serialização e versão declarados, com testes determinísticos.
7. A camada de dados cria banco SQLite local, registra versão de schema e aplica
   migrações em transação; nenhum dado de produto é apagado.
8. A documentação de desenvolvimento informa pré-requisitos (Node, Python e
   Rust), comandos e limites desta fundação.
9. Nenhum código desta story altera ou replica a fórmula Lotofácil, e nenhum
   comando gera ou imprime jogos.
